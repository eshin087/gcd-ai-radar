# Security, performance and scaling audit

Audit date: 2026-10-18, against `main` at the "disclosed vulnerabilities" release. Scope: the public static site (Next.js 16 export on Vercel Hobby), the collector (TypeScript on GitHub Actions every six hours, LLM classification) and the data files in git. Design target agreed with the owner: ten years and about 60,000 records.

## Where things stand, measured

| Measure | Value |
|---|---:|
| Records published | 1,911 (402 incidents, 1,509 disclosed vulnerabilities) |
| Growth, last six months | 100–210 records a month, mostly disclosed CVEs; incidents 5–20 a month |
| `data/incidents.json` | 2.4 MB pretty-printed, about 1.25 KB a record |
| Git repository, packed | 1.5 MiB |
| Build output | 405 MB, 13,473 files, 14 s for 1,919 pages |

| Explorer dataset `incidents.min.json` | 1.33 MB (162 KB compressed), downloaded whole by the Incidents page and the report drawer |
| JavaScript, all chunks | 677 KB (185 KB compressed) |
| One incident page | 78 KB HTML + 42 KB payload (7 KB compressed) |
| Scheduled collector run | 15 fetched, 1 classified, 1 LLM call, 15 minutes (GDELT pacing) |
| `npm audit` | 5 high, 4 moderate, all in build- or dev-only chains (details below) |

Vercel Hobby limits that matter: 100 GB of fast data transfer and 1,000,000 CDN requests a month included; builds stop at 45 minutes; 100 deployments a day (the collector uses four plus manual ones); CLI uploads are capped at 100 MB and 15,000 source files (`.vercelignore` keeps us under); there is no cap on build output files, but Vercel warns that builds slow past about 100,000 of them. GitHub: a file over 50 MiB warns, over 100 MiB is blocked; repositories should stay under 1 GB.

## Fixed in this audit

1. **Workflow command injection.** `collect.yml` interpolated the `source` input of a manual run straight into a shell script. Only people with write access can dispatch the workflow, so the exposure was small, but the pattern is the classic one. Inputs now reach the script only as environment variables.
2. **Actions pinned to commit SHAs** (`actions/checkout`, `setup-node`, the Pages actions) instead of floating major tags, with version comments. A new `.github/dependabot.yml` keeps the pins and npm dependencies current (weekly, minor and patch bumps grouped).
3. **Links restricted to web URLs.** The schema accepted any URL scheme for a source, and the incident page renders sources as `<a href>`. The collector already dropped non-HTTP candidates, but seeds and manual edits did not go through that path. `SourceSchema.url` and the Radar attribution URL now require `http` or `https`; every stored URL already complied.
4. **CSV formula injection.** A title beginning with `=`, `+`, `-`, `@`, tab or carriage return would run as a formula when the public CSV is opened in Excel or LibreOffice. Cells are now prefixed with a quote (`lib/csv.ts`, tested).
5. **Security headers** (`vercel.json`): a content-security policy that allows only same-origin scripts, styles, fonts, images and fetches, blocks embedding (`frame-ancestors 'none'`, `X-Frame-Options`), plus `nosniff`, a strict referrer policy and a permissions policy. The policy shipped as report-only first and was switched to enforcing once the live site showed no violations. The static export has no nonces, so inline scripts and styles stay allowed; remote script origins, object embeds and framing are blocked. The dataset, feed and chart images get `Access-Control-Allow-Origin: *` (it is a public dataset) and a one-hour cache.
6. **Prompt injection.** Fetched titles and descriptions go to the classifier verbatim. A crafted page could ask the model to classify it as a real-world incident with its own title and summary; HN and GDELT are open, so anyone can get a URL in front of the classifier. The output schema already bounds what gets through (enum fields, length caps, a confidence threshold), and the site renders all text escaped, so the worst case is a misleading record, not code execution. Both prompts now state that item text is untrusted data and never instructions.
7. **Silent failure.** If every LLM provider is down or out of quota, nothing visible breaks: the site keeps building from old data while candidates pile up. The collector now writes a job summary to the Actions run page and fails the job after three consecutive scheduled runs that classified nothing while candidates waited (`settings.alerts`), so GitHub emails the owner. Dry runs and manual runs never trigger it.

## Second pass, same day: full security audit

The owner asked for a full pass with everything fixable fixed. The threat model and the controls now in place are written up in `docs/security.md`. Added on top of the first pass:

8. **Outbound network guard.** Every collector fetch, and every redirect hop, must be http(s) to a public address; loopback, private, link-local (cloud metadata), carrier-grade NAT, multicast and reserved ranges are refused, and hostnames are checked against every address they resolve to (`collector/lib/netguard.ts`, tested). Redirects are followed by hand, at most five hops, and credential headers are dropped when a redirect changes host. The AI Incident Database export, which bypassed the shared client, now downloads through it with a timeout and a 50 MB cap.
9. **XML entity expansion.** DOCTYPE declarations are stripped before feeds and sitemaps are parsed, so a "billion laughs" document cannot exhaust the runner (tested with one).
10. **Install scripts off.** `npm ci --ignore-scripts` in every workflow; the native binaries (esbuild, sharp, the Tailwind and resolver helpers) arrive as optional packages and need no script. Verified: tests, lint and the production build pass without scripts.
11. **Two advisories fixed by overrides.** `fflate` 0.7.5 and `uuid` 11 (the Excel library round-trips a workbook with it). The remaining `braces` advisory has no fixed release; it sits under ESLint and reads only our own patterns.
12. **Credentials dropped from checkouts that do not push** (`persist-credentials: false` in CI and the Pages fallback).
13. **Weekly dependency audit** (`audit.yml`) that fails on a high advisory in a runtime dependency or a critical one anywhere, so the owner is emailed; Dependabot no longer proposes routine major bumps, only minor and patch groups and whatever a security advisory needs.
14. **CodeQL** static analysis of the TypeScript on every push, pull request and weekly, with the security-and-quality query pack; findings appear under Security → Code scanning.
15. **Markdown on the Sources page** renders text and links only; raw HTML in the file is dropped.

## Accepted for now

- `npm audit`: `braces` (stack exhaustion on deeply nested glob patterns) has no fixed release and sits under ESLint, which only reads our own lint patterns. The `fflate` and `uuid` advisories were closed in the second pass with version overrides.
- The content-security policy needs `'unsafe-inline'` for scripts and styles because a static export cannot carry per-request nonces. It still blocks third-party scripts, embedding and object plugins.
- `fetch-depth: 0` in `collect.yml` clones the whole history every six hours. At 1.5 MiB that is free; switch to a shallow checkout when the repository passes about 100 MB (the rebase-and-retry push works in a shallow clone).

## What breaks at what size

The site is fully static and the collector's work per run depends on the feeds, not on the dataset, so most things scale for free. Four do not. At today's pace (100–210 records a month) the first wall is two to three years away; at the 60,000-record target all four need the restructure described below.

| Component | Today | At 10,000 records | At 60,000 records | Breaks at about |
|---|---:|---:|---:|---|
| Home page HTML (every row embedded) | 1.07 MB / 87 KB compressed | 5.6 MB / 450 KB | 34 MB / 2.7 MB | 8,000–10,000 records: slow on phones, heavy on the transfer allowance |
| Explorer download `incidents.min.json` | 1.33 MB / 162 KB | 7 MB / 850 KB | 42 MB / 5 MB | 10,000 records |
| `data/incidents.json`, one file rewritten four times a day | 2.4 MB | 12.5 MB | 75 MB, over GitHub's 50 MiB warning and near the 100 MiB block | 15,000 records (unwieldy), 40,000 (hard) |
| Related incidents at build (`relatedIncidents` scores every record against every other) | 3.6 million comparisons, instant | 100 million, seconds | 3.6 billion, minutes to hours, in each of ten build workers | 20,000–30,000 records, against the 45-minute build cap |

Smaller items: per-incident pages are about 120 KB each on disk (Next writes the page and its navigation payload, and embeds the payload again inside the HTML), so 60,000 records mean roughly 7 GB of build output and 120,000 files plus 60,000 per-incident JSON files. Vercel allows it but builds slow down; trimming the page (fewer wrapper classes, no definition tooltips on related-incident chips, four related incidents instead of six) would cut it by about 40%. `seen.json` keeps every URL ever considered (3,567 entries now) and should drop rejected URLs older than the dedupe window once it passes a few hundred thousand entries.

### The restructure (one change, before about 8,000 records)

- **Shard the data by year.** `data/incidents/2026.json` and so on; the collector loads every shard and writes back only the years it touched, so a run rewrites one small file. The site's loaders read the directory. Public downloads keep `incidents.json` whole (regenerated at build) and add per-year files.
- **Dashboard from aggregates.** Precompute at build, per month: counts by family, type, severity, target, and the disclosed series, for both date bases. That is a few kilobytes however large the dataset. The page renders charts and tiles from it immediately and fetches year shards of compact rows only when a number is clicked (the drawer) or the window changes, so the "All" window loads everything but only on request.
- **Explorer from shards plus an index.** Load the current year first, older years as the filters or the scroll need them, and a prebuilt compact search index (id, title and product tokens) so search never needs the whole dataset.
- **Related incidents from an index.** Bucket records by category and product and by year, and score only candidates that share a bucket within a year either side. Linear instead of quadratic.
- **Keep prerendering every incident page.** Each incident needs a crawlable, citable URL; the cost is build time and output size, both within limits at 60,000 with the trims above.

Estimated effort: about two days, mostly in the collector state module, `lib/data.ts`, `lib/dashboard.ts`, `useDashboardModel` and the explorer. Nothing in the data model changes.

### Restructure: done (2026-10-18)

All four changes landed in one branch; the record schema and the counting rule are untouched.

- **Shards.** `data/incidents/<year>.json` by year of first report (`lib/shards.ts`). `saveState` serializes every shard and writes back only those whose bytes changed, removes a shard left empty and the pre-shard `incidents.json`; a checkout that still has only the old single file loads it and is converted on the next save (`scripts/shard-incidents.ts` does it by hand, and refuses when both layouts are present). The site loaders read the directory once per build worker and reuse the parse while the files' mtimes stand. Downloads keep `incidents.json`, `incidents.min.json` and `incidents.csv` whole and add `years/<year>.json`.
- **Aggregates.** `lib/aggregates.ts` precomputes, per month and for both date bases, counts by type, category, severity and target for all incidents and for the real-world set, the disclosed series with its product breakdown, the headline numbers and the newest incidents. The page ships that and a shard manifest; `public/data/rows/<year>.json` (compact rows) is fetched only when a drawer opens, and only the years the selection can touch. Year-only incident dates are kept apart in the cells (`yearOnly`) because window totals place them in July and monthly columns cannot place them at all; the drawer for a column now lists exactly what the column counted (it used to add year-only records in July).
- **Explorer.** Loads `public/data/slim/<year>.json` for the current year first and older years when filters, sort or the list's length need them (`lib/explorer.ts`); the search box uses a token index over id, title and products (`public/data/search-index.json`, `lib/search.ts`), so it no longer matches summaries.
- **Related incidents.** `lib/related.ts` buckets records by category, product and target per year and scores only candidates sharing a bucket within a year either side (every year when that cannot fill the list). Over all 1,911 records, 89.2% of lists are identical to the full scan; the rest swap a record from two or more years earlier for one from the window.

Measured at 1,911 records (`npm run build`, sizes on disk and brotli-compressed):

| File | Before | After |
|---|---:|---:|
| `index.html` | 1,071 KB / 85 KB | 263 KB / 21 KB (of which 90 KB is the aggregate payload; the rest is chart markup, unchanged) |
| Home navigation payload `index.txt` | 808 KB / 72 KB | 84 KB / 9 KB |
| Explorer first download | `incidents.min.json` 1,335 KB / 158 KB | `slim/2026.json` 778 KB / 93 KB (the current year holds 60% of the records) |
| Drawer download | `incidents.min.json` 1,335 KB | `rows/2026.json` 470 KB / 41 KB, then `slim/<year>.json` for the summaries on screen |
| Search | in the download above | `search-index.json` 197 KB / 41 KB, fetched on first use |
| Static pages | 13 s for 1,919 pages | 5 s |

The aggregate payload grows with months and distinct products, not records: about 200 KB uncompressed at ten years. A year shard grows with the year's records; at 6,000 records a year the explorer's first download is about 4 MB (500 KB compressed), the point at which the slim shards should be split by quarter.

Checks: `tests/aggregates.test.ts` compares every clickable number with the rows its drawer lists for every window, date basis and incident set, on the live data and on fixtures with awkward dates; `tests/shards.test.ts` covers the shard writer; `tests/related.test.ts` the parity above; `scripts/check-drawers.mjs` clicks the numbers in headless Chrome against the static export (92 of 92 matched).

## Long-term risks and dates

- **Node 22 reaches end of life in April 2027.** `engines` pins `22.x` and Vercel will stop building on it some months later. Move to Node 24 in the first quarter of 2027: `package.json` engines, the Actions `node-version`, and the local toolchain. Vercel's project default is already 24.
- **LLM free tiers** change without notice. Model ids and daily budgets live in `collector/config/settings.json`; the router falls through Gemini Flash-Lite, Gemini Flash and Groq. Steady state uses one to ten calls a run against a 500-a-day allowance. The new stall alarm covers the case where every provider fails.
- **GitHub Actions** disables schedules after 60 days without activity; the collector's own commits are activity and `keepalive.yml` re-enables the workflow weekly regardless. Scheduled runs have started up to 3.5 hours late, which is normal for GitHub's queue.
- **Vercel Hobby** is for non-commercial use; the site qualifies. The 100 GB monthly transfer allowance is the quantity to watch: a home-page visit costs about 300 KB today (roughly 330,000 visits a month), but would cost about 3 MB at 60,000 records without the restructure (roughly 33,000 visits). That is the reason the home page must stop embedding every record.
- **NVD without an API key** is limited to 5 requests per 30 seconds. The incremental window needs a handful of requests a run, so it is fine; only full backfills are slow.
- **Source terms** are reviewed on the Sources page; a feed that starts blocking shows up in the run summary as "not ok".

## Repository settings worth turning on (need your click)

Files only were in scope for this audit. These are settings:

- **Dependabot alerts and security updates** (Settings → Code security and analysis). The new `dependabot.yml` handles version bumps; vulnerability alerts need this switch. Left off by the owner's choice; the weekly `audit.yml` covers the same ground by email.
- **Secret scanning with push protection.** Already on: GitHub enables both by default on public repositories. Because push protection also scans the collector's automated data commits, a rejected push now fails the collector job so the owner hears about it.
- **A branch rule for `main`** that blocks force pushes and deletion. Created on 2026-10-18 as the ruleset "protect main". It requires no reviews and no status checks, so the collector's direct pushes continue.
- **Actions permissions.** Keep the default of read-only `GITHUB_TOKEN`; `collect.yml` and `keepalive.yml` declare the write scopes they need.
- **Vercel.** Keep preview protection on. Nothing else to change.
